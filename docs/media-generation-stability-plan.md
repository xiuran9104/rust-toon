## 第一轮实现与边界（2026-09-17）

- 新视频归档后，在同一事务中保存视频文件路径、`generation_context.quality` 和 `toon.video_quality` 持久任务。Worker 完成基础检查后才将视频标记为生成成功；任务中心可查看质检任务。
- 基础检查包含 FFprobe 元信息、完整音视频解码、请求时长、显示比例、所需音轨，以及黑场/冻结提醒。黑场和冻结可能是创作意图，只提示人工复核；通过基础检查不代表人物、动作、口型或叙事质量通过。
- 在 `generation_context.request` 保存最终提示词、模型配置标识、参数与实际有序参考图。它是请求快照，尚不是带完整资产版本和语义角色的 `ReferenceManifest`；模型配置标识也不等同于供应商模型版本快照。
- 多参考模式超过当前应用上限 4 张时明确失败；首尾帧模式从完整分镜序列取端点，不能先截断再取尾帧。不存在的 `@图N` 引用在供应商调用前拦截。
- `previous_tail` 为严格连续策略：只复用通过基础质检的前片；本次批量任务依赖本次前片的具体视频 ID。前片失败时下游停止，不复用旧成功版本、不自动退回本轨首帧。需要独立生成时，用户可明确改选 `own`。
- 继承尾帧时替换当前首帧，保留目标尾帧；仅提供尾帧的模式会在尾帧之前补入继承首帧。文本参考模式与严格尾帧策略不兼容，提交时明确报错。
- 独立批量入口和工作流视频节点共用依赖调度器。独立批量并发为 2，工作流继续使用已有并发设置。
- 旧视频保留播放/选用能力，显示“尚未质检”；用于严格连续镜头前须通过“检查质量”执行检查。检查不会再次调用视频生成供应商。
- 质检租约与最终视频/任务状态在同一事务提交，Gateway 重启不会将有效质检任务标记失败。取消/删除优先于晚到结果，质检执行重试耗尽会结束视频任务。

本轮复用现有 JSONB 字段和通用任务表，没有修改数据库结构或基线数据。完整 Agent/Workflow 运行仍在 Gateway 进程内；此轮仅质检持久化，尚不支持整个工作流重启续跑，Gateway 必须保持单副本。

后续重点：共享完整资产引用清单、模型能力驱动的参数编译、人物/动作/口型视觉质检、人工审核记录、有限付费重生成、时间线转场与混音、连续预览。以下原始问题清单是计划制定时的记录，当前实现以本节和代码为准。

## 背景与结论

当前图片和视频出现主体错误、角色漂移、场景混淆、构图偏离等问题，不能只通过追加自然语言提示词解决。现有链路的主要风险是：视频提示词没有获得完整的资产与参考图映射，参考图顺序可能与 `@图N` 不一致，超过供应商上限的参考图会被静默截断，且不同用途的参考图没有被稳定地区分。

下一轮必须优先把生成过程改造成“结构化描述 → 确定性参考映射 → 模型专用编译 → 生成前校验 → 生成后质检”的闭环，再继续微调提示词文案。

## 已确认的问题

1. 视频提示词生成只读取分镜画面、运动和时长，没有同时提供资产名称、类型、ID及其 `@图N` 映射。
2. 轨道资产参考图按文件路径排序，不能保证与分镜绑定顺序或提示词引用顺序一致。
3. 视频参考图目前最多保留四张，超出部分会被静默截断，提示词却可能继续引用被删除的资产。
4. 文本模式会把分镜帧、人物、场景和道具都作为普通参考图发送，供应商无法可靠判断每张图的用途。
5. 分镜图片统一要求所有绑定资产清晰可见，容易与特写、背影、空镜头及景别要求冲突。
6. 当前真实供应商 E2E 只验证能否返回 URL，尚未验证人物、场景、动作和首帧一致性。

## 目标架构

每次生成先形成一份不可变的生成快照，后续提示词和供应商请求只能从该快照生成：

```text
分镜与资产
  -> 结构化镜头描述
  -> 有序 ReferenceManifest
  -> 模型专用 Prompt/Payload 编译器
  -> 生成前校验
  -> 供应商生成
  -> 视觉质检
  -> 有针对性的有限重试
```

建议的参考清单结构：

```json
{
  "references": [
    { "index": 1, "kind": "first_frame", "url": "..." },
    { "index": 2, "kind": "required_subject", "assetId": 101, "assetType": "role", "name": "沈辞", "url": "..." },
    { "index": 3, "kind": "identity_reference", "assetId": 102, "assetType": "role", "name": "苏锦", "url": "..." },
    { "index": 4, "kind": "environment_reference", "assetId": 203, "assetType": "scene", "name": "城楼", "url": "..." }
  ]
}
```

## 下一轮实施顺序

### P0.1 确定性参考图清单

- 新增统一的 `ReferenceManifest`，保存序号、用途、资产 ID、资产类型、名称和 URL。
- 分镜图片、视频提示词、视频 payload 共用同一份清单。
- `@图N` 只能由服务端根据清单生成，Agent 不得自行猜测编号。
- 禁止按文件路径重新排序。
- 在任务记录中保存最终清单，确保问题可以复现。

### P0.2 结构化镜头描述

- Agent 先生成受约束的镜头 JSON，不直接生成最终供应商提示词。
- 至少包含主体、资产 ID、动作、位置、场景、景别、运镜、情绪、时长、台词和音效。
- 明确区分 `required_subject`、`identity_reference` 和 `environment_reference`。
- 服务端校验结构化数据与分镜及资产绑定一致后，才进入提示词编译。

### P0.3 模型专用编译器

- 为 Seedream、Seedance、Wan 等模型分别实现 Prompt/Payload 编译器。
- Seedance 明确发送 `first_frame`、`last_frame` 和 `reference_image`。
- 每个编译器声明支持的模式、参考图数量、分辨率、时长及音频能力。
- 不支持的组合必须返回明确业务错误，禁止自动退化成含义不同的模式。

### P0.4 参考图上限策略

参考图超限时按以下优先级选择：

```text
首帧/尾帧 > 当前镜头主体 > 关键道具 > 场景 > 非主体身份参考
```

- 被舍弃的引用必须记录原因。
- 最终提示词不得引用已被舍弃的 `@图N`。
- UI 和任务详情应展示实际发送的参考图，而不是仅展示原始绑定。

### P0.5 生成前校验

供应商调用前至少检查：

- 每个 `@图N` 都存在且与清单一致；
- 引用数量没有超过模型上限；
- 首尾帧模式包含正确数量的帧图；
- 空镜头没有错误绑定必须出镜人物；
- 特写、背影等镜头没有被强制要求所有资产完整可见；
- 提示词、比例、分辨率、时长和音频参数符合模型能力；
- 远程参考图可被供应商访问。

校验失败必须停止生成并返回具体原因。

### P1 生成后视觉质检与重试

- 图片检查人物数量与身份、场景、服装、景别、动作、比例、文字和水印。
- 视频检查首帧相似度、身份稳定性、动作方向、镜头运动、闪烁和形变。
- 质检结果结构化保存，并给出失败项和置信度。
- 自动重试最多两次，只针对失败项生成修复指令；禁止无限重试。
- 两次仍失败时保留全部快照并交由人工处理。

### P1 可观测性与回归样例

每次任务保存以下信息：

- 原始分镜与资产绑定；
- 结构化镜头描述；
- `ReferenceManifest`；
- 最终提示词和供应商 payload（凭据必须脱敏）；
- 模型、模式和参数；
- 供应商任务 ID、错误和原始响应摘要；
- 质检结果及每次重试原因。

建立一组固定的小型回归集，至少覆盖单人、双人、场景、关键道具、特写、背影、空镜、首帧和首尾帧视频。

## 验收标准

下一轮不能只以“接口成功并返回 URL”作为完成标准，至少满足：

1. 同一任务重复执行时，参考图顺序和 `@图N` 映射完全一致。
2. 单元测试覆盖参考排序、去重、超限选择、提示词引用和模型模式编译。
3. 集成测试能够捕获提示词引用不存在、首尾帧缺失和模型参数不支持。
4. 真实供应商 E2E 保存生成快照，并对固定样例执行视觉质检。
5. 任意失败都能从任务详情定位到结构化输入、最终提示词、实际参考图和供应商参数。
6. 不允许静默截断、静默换模式、返回伪成功或只记录一个笼统的“生成不正确”。

## 暂不作为首要方案

- 在现有长提示词末尾继续追加更多禁止项；
- 单纯提高模型温度或反复随机重试；
- 只更换供应商而不修复引用映射；
- 要求所有参考资产在所有镜头中完整出现。

这些方式可能偶尔改善单张结果，但无法形成可复现、可诊断的稳定生成链路。
